# 簡單條碼開發文件

## 專案概觀

本專案是單一 Android Application Module，最低支援 Android 8.0（API 26），目標 SDK 為 36。介面使用 Jetpack Compose，桌面小工具使用原生 `RemoteViews`，條碼編碼使用 ZXing Core。

## 專案結構

```text
app/src/main/java/com/simplebarcode/app/
├── MainActivity.kt                 APP 進入點
├── MainViewModel.kt                畫面資料與操作協調
├── SimpleBarcodeApp.kt             Compose 畫面與導覽
├── barcode/
│   ├── BarcodeGenerator.kt         條碼驗證與 Bitmap 產生
│   └── BarcodeSharing.kt           PNG 分享
├── data/
│   ├── BarcodeItem.kt              條碼格式與資料模型
│   ├── BarcodeRepository.kt        條碼本機儲存
│   └── SettingsRepository.kt       主題、Hue 及顯示模式設定
├── ui/theme/
│   ├── Theme.kt                    預設與自訂 Hue 主題配色
│   └── SystemBars.kt               系統列顏色與圖示同步
└── widget/
    ├── BarcodeWidgetProvider.kt    小工具更新與尺寸處理
    ├── WidgetConfigActivity.kt     小工具條碼選擇畫面
    └── WidgetStore.kt              小工具與條碼關聯
```

## 資料儲存

條碼及設定目前使用 Android `SharedPreferences` 儲存在應用程式私有目錄：

- `barcodes`：JSON 格式的條碼清單。
- `settings`：預設主題索引、自訂 Hue、主題來源及顯示模式。
- `widget_selections`：App Widget ID 與條碼 ID 的對應。

這些資料不會透過網路傳送。若未來增加資料庫或備份功能，需要規劃既有資料遷移。

## 條碼產生

`BarcodeGenerator` 負責：

- 依條碼類型執行長度及字元檢查。
- 呼叫 ZXing `MultiFormatWriter` 建立矩陣。
- 將矩陣轉換成黑色線條及白色背景的 `Bitmap`。
- 保留條碼左右必要留白，避免主題色影響掃描。

新增條碼類型時，需同步更新：

1. `BarcodeType` 列舉。
2. `BarcodeGenerator.validate()` 的格式驗證。
3. 單元測試及繁體中文文件。

## 桌面小工具

小工具以 `RemoteViews` 顯示條碼 Bitmap。`BarcodeWidgetProvider` 會讀取啟動器提供的最小寬高，依裝置密度重新產生條碼圖片。

目前配置原則：

- 條碼使用名稱以外的全部可用高度。
- 名稱固定顯示在條碼下方，使用小字及單行省略。
- 條碼維持白色背景。
- 小工具使用無外框的白色圓角背景，不跟隨 App 主題色。
- 點選小工具會開啟對應條碼的 APP 詳細頁。

條碼建立、修改或刪除後，`MainViewModel` 會要求所有小工具重新繪製。主題設定不影響小工具，因此不會觸發小工具刷新。

## 主題系統

`Theme.kt` 定義六個 `ThemeOption`，每個選項包含 Hue、主色、深色模式主色及容器色。自訂主題透過 Hue 產生淺色與深色配色，並依背景亮度選擇高對比前景色。顯示模式分為跟隨系統、淺色及深色。

`SettingsRepository` 保留既有 `theme_index`，並持久化自訂 Hue 與預設／自訂主題來源。選擇預設色會同步 Hue 滑桿位置，拖曳滑桿則立即切換為自訂主題。

Compose Theme 更新後，`SyncSystemBars` 會同步調整狀態列、系統導覽列及圖示明暗。條碼圖片不跟隨深色模式，以維持掃描對比。

## 建置指令

執行單元測試：

```powershell
.\gradlew.bat testDebugUnitTest
```

執行 Android Lint：

```powershell
.\gradlew.bat lintDebug
```

建立 Debug APK：

```powershell
.\gradlew.bat assembleDebug
```

建立 Pre-release APK：

```powershell
.\gradlew.bat assemblePrerelease
```

`prerelease` Build Type 繼承 Release 的 R8 與 ProGuard 設定，版本名稱加上 `-prerelease`，並使用 Debug signing config。APK 輸出於 `app/build/outputs/apk/prerelease/app-prerelease.apk`。

完整驗證：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

## Pre-release 發布規範

目前 GitHub Release 屬於測試用途，發布時應遵守：

- GitHub Release 必須設為 `Pre-release`。
- Tag 使用 `v<版本>-prerelease` 格式。
- Release 標題及說明必須清楚標示 `Pre-release`。
- APK 使用 `prerelease` Build Type 建置，啟用 R8 並以 Debug 金鑰簽署。
- Release Notes 必須註明不是正式版本。
- 不應將 Pre-release APK 宣稱為正式、安全或可長期保存資料的版本。

正式發行前仍需建立正式簽章、保護簽章資訊、完成實機與多啟動器測試，並改用 Release APK 或 Android App Bundle。

## 測試重點

- 每種條碼格式的有效及無效內容。
- 淺色、深色、六種預設主題與自訂 Hue 即時切換及持久化。
- 三鍵導覽及手勢導覽的系統列顏色。
- 不同桌面格數、密度及啟動器的小工具顯示。
- 條碼更新、刪除後的小工具同步。
- 分享 PNG 在不同 Android 版本的相容性。
